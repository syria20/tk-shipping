# ui/: T.K UI v2 (design system + new screens)

New screens built on `replica/design/` (Arabic RTL, German LTR, iPhone and
desktop). Everything here is **off by default**.

## Turn it on or off (per browser)

- On: open the app with `?ui=2` (for example `index.html?ui=2`). The choice is
  stored in `localStorage["tk-ui2"]`.
- Off: open with `?ui=0`.
- Switch off single screens while the rest stay on:
  `localStorage.setItem("tk-ui2-off", "detail,ships")`.

Customers who never open `?ui=2` see the app exactly as before.

## Files

| file | what |
| --- | --- |
| `tokens.css` | design tokens, generated by `replica/design/build_tokens.py` (do not edit by hand) |
| `tk-ui.css` | contrast bridge for the old views, desktop shell, styles for new screens; all scoped to `html.tk-ui2` |
| `tk-ui.js` | switch, screen registry, AR/DE/EN text, money/LTR formatting |
| `screens/shipments.js` | S07 My shipments (`ships` view) and S08 Shipment detail (`detail` view) |

## How it hooks into the app

`index.html` and `admin.html` only got lines added (nothing removed):

1. In `<head>`: the two stylesheets and the scripts above.
2. In `index.html` `draw()`, one guard before the old views:
   `if(window.TKUI&&TKUI.on(v)&&(h=TKUI.render(v,s))){}else ...`
   When the switch is off, or a new screen fails, the old view renders.

New screens make **no Supabase calls**. They read the state the app already
loaded and reuse the app's own functions for every action (rating, document
upload, invoices, proof of delivery, repeat shipment).

## Remove completely

Delete the added lines in both HTML files (marked
`<!-- T.K UI v2 ... -->` and the `TKUI` guard in `draw()`), then delete `ui/`.
